# Working in Fylgja

Fylgja is a local macOS daemon: Python 3.13, uv, FastAPI/Uvicorn on `127.0.0.1:7319`, SQLite. See
[`README.md`](README.md) for what it does and how to run it.

## Check before you commit

CI runs exactly this; run it before every commit.

```sh
uv lock --check
uv sync --frozen --all-groups
uv run --frozen ruff format --check .
uv run --frozen ruff check .
uv run --frozen mypy src/fylgja
uv run --frozen pytest -m "not live" --cov=fylgja --cov-branch --cov-fail-under=85
```

- `FYLGJA_RUN_SLOW=1` adds the `slow` tests (CI runs them on macOS).
- `FYLGJA_RUN_LIVE=1` runs the `live` tests against installed tools; they are never part of CI.
- Pre-commit runs `uv-lock`, `ruff check --fix` and `ruff format`.

## Layout

| Path | Holds |
|---|---|
| `src/fylgja/_entry.py`, `hook.py`, `paths.py` | Console script and hook path; stdlib only |
| `src/fylgja/collectors/<name>/` | `plugin.py` descriptor, `adapter.py` I/O, `parse.py` pure parsing |
| `src/fylgja/core/` | Daemon, single writer, resolver, sessions, ranking, summaries |
| `src/fylgja/store/` | SQLite access and `migrations/` |
| `src/fylgja/api/` | FastAPI app, routes, security guards, SSE, the page in `static/` |
| `src/fylgja/cli/` | Typer CLI, HTTP client, `install`, `doctor` |
| `src/fylgja/testing/` | Public fakes and the collector contract suite |
| `tests/` | `unit/`, `contract/`, `integration/`, `live/`, `fixtures/`, `fake_plugins/` |
| `scripts/`, `spikes/` | Dev-only generators and tools; not packaged |
| `docs/` | API, collectors, decisions, revalidation logs, runbooks, the plan |

## Architecture rules

- **One writer.** Only the daemon writes SQLite. The CLI is an HTTP client of the daemon; `hook`, `serve`,
  `doctor` and `install` are the only exceptions.
- **Hook path is stdlib only.** `_entry.py` dispatches `hook` before importing Typer, FastAPI or Pydantic.
  `hook.py` imports only the stdlib and `fylgja.paths`. A test enforces this.
- **Fixed dependencies.** Runtime: `fastapi`, `pydantic`, `typer`, `uvicorn`. Ask before adding one; run
  `uv lock` after any change.
- **Independent of Lidskjalv.** Fylgja never reads Lidskjalv's repository, cache or hooks, at runtime or in
  tests.
- **Every mutating route** goes through the guards in `api/security.py`: bearer secret, Origin,
  `Content-Type`, body size. Every route checks the `Host` header.
- **Model calls** (summaries) run only in the daemon, off by default, with the recursion-guard variables set.
- **New collectors** register under the `fylgja.collectors` entry point and pass `fylgja.testing.contract`.

## Tests

- An autouse fixture points `HOME` and `FYLGJA_*_DIR` at `target/tests/`. Never read the real home directory and
  never bind port 7319.
- External commands go through `FakeProcessRunner`, and time comes from `FakeClock`. Tests need no AeroSpace,
  cmux, gh, agent CLI, network or Lidskjalv.
- Subprocess tests use `sys.executable`. Mark tests over about 2 s `slow`. Mark macOS-only tests with
  `skipif(sys.platform != "darwin")`.
- Tests never write tracked files. Goldens, schemas and fixtures are regenerated by hand with `scripts/gen_*.py`.
- Fixtures are sanitized with `scripts/sanitize_fixture.py`. `test_fixture_hygiene.py` rejects home paths, email
  domains, socket keys and the names in the gitignored `tests/fixture-denylist.local.txt`. Never commit SQLite
  files.

## Safety on a live machine

Fylgja runs next to real work sessions. When you explore or debug:

- Run nothing that writes to `~/dotfiles`, `~/.claude`, `~/.config`, `~/.local` or `~/Library`. That includes
  `fylgja install … --apply` against the real home.
- Do not run `osascript`; it can raise a permission prompt nobody answers.
- Do not start, stop or focus apps, windows, sessions or launchd jobs.
- Never read `~/.claude/sessions/*.key` or another process's environment (`ps e`). Never print
  `CLAUDE_CODE_MESSAGING_TOKEN`, `CMUX_SOCKET_CAPABILITY` or the API secret.
- To try the daemon, point `HOME` and `FYLGJA_*_DIR` at a scratch directory.

## Documentation

- Committed docs record shapes, field names, counts and versions. Never put window titles, prompts, transcript
  text, customer names or tokens in them.
- A decision that changes or refines the plan gets a record in `docs/decisions/NNNN-<slug>.md`, using the
  next free number and the header format of the existing records.
- [`docs/PLAN-final-plan.md`](docs/PLAN-final-plan.md) is the plan. Code cites it as `PLAN-final-plan.md §x`.
  `test_decision_log.py` checks its amendment table against `docs/decisions/`.

## Commits

Short conventional subjects (`fix:`, `docs:`, `chore:`, `feat:`). Say what changed, not how the work was done.
