# Presence signals revalidation, 2026-10-06 (WP5.1, A17)

Source: `PLAN-final-plan.md` §5 WP5.1 ("Revalidate on macOS 27"), A17 and §4.4; `research/04-app-activity.md` (the
Generic and Teams/call sections). The machine runs macOS 27.0.1 with Python 3.13.5. Every probe is read-only and
runs from my own shell through `spikes/presence_probe.py`, which calls the collector's own adapter
(`fylgja.collectors.presence.adapter.SystemSignals`) and prints one line per signal. It reads device state only:
no audio, no video, no window contents, and it writes nothing. Nothing was started, locked, focused or recorded.
Values here are field names, counts and times.

The plan requires all four signals to work from the **launchd** context without a prompt. That context cannot be
tested here (`launchctl submit` and `bootstrap` are not allowed), so it is recorded as `unknown` with the exact
by-hand check. Nothing failed from the shell, so no decision record is needed: a signal that fails later is reported
as `degraded` by design (the collector names it in `doctor()`), which `docs/collectors/presence.md` documents.
