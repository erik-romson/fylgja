# User-level skill revalidation, 2026-10-06 (WP4.4, A18)

Source: `PLAN-final-plan.md` §5 WP4.4 ("How the skill passes the session id is revalidated against the skills docs")
and A18 (Fylgja never injects into model context and adds no synchronous hook). The only command is a `curl` of the
official Claude Code skills page, saved under `target/fixture-staging/skills/` (gitignored) and searched with `grep`.
Nothing was started or written outside that directory. Values here are field names, placeholder names and versions.

| Claim | Command run | Observed | Verdict | Action |
|---|---|---|---|---|
| A user-level skill receives the current session id as a placeholder in its markdown content (`PLAN-final-plan.md` WP4.4, A18) | `curl -sSL -m 30 -o skills.md https://code.claude.com/docs/en/skills.md`; `grep -n 'CLAUDE_SESSION_ID' skills.md` | The "Available string substitutions" table lists `${CLAUDE_SESSION_ID}` ("The current session ID"). It is substituted in the skill content before Claude sees it. The page also lists `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}` and `${CLAUDE_EFFORT}`. | holds | The template writes `fylgja todo add --session ${CLAUDE_SESSION_ID} …`; no hook, file or environment variable is involved |
| The text typed after `/fylgja-todo` is available as `$ARGUMENTS` | `grep -n 'ARGUMENTS' skills.md` | `$ARGUMENTS` expands to "all arguments passed when invoking the skill", as typed. An argument that itself contains `$1` or `$ARGUMENTS` is inserted as literal text and not expanded again. When no placeholder receives the argument, Claude Code appends `ARGUMENTS: <value>`. | holds | The template uses `$ARGUMENTS` once, inside the command, so the user's text is never appended twice |
| `${CLAUDE_SESSION_ID}` is substituted only in a local session | `sed -n 293p skills.md` | In "any other session on your machine" (a remote or non-local session) the placeholders reach Claude as literal text; this handling needs Claude Code v2.1.228 or later. | holds | The template tells Claude to stop and say so when the id is empty or starts with `$`, and not to guess an id; `fylgja todo add` without `--session` would file the todo under the focused workspace, which the user did not ask for |
| `$ARGUMENTS` is pasted into the content, so shell quoting is Claude's job, not Claude Code's | `grep -n 'literal text' skills.md` | The docs describe text substitution only and give no shell-escaping rule. Indexed placeholders (`$0`, `$1`) use shell-style quoting to split the typed text, and `$ARGUMENTS` is "the full argument string as typed". | unknown | The template says to pass the text as one single-quoted argument, with an embedded `'` written as `'\''`, and the todo text is never run through another shell. Run by hand in a session: `/fylgja-todo it's a "test" $HOME` and check that `fylgja todo ls --session <id>` shows that exact text |
| A skill can pre-approve its one command and be hidden from automatic use | `grep -n 'allowed-tools\|disable-model-invocation' skills.md` | `allowed-tools` pre-approves tools "during the turn that invokes this skill" (Bash rules use `Bash(<command> *)`); `disable-model-invocation: true` stops Claude from loading the skill by itself and keeps it for `/name`. | holds | The template sets `disable-model-invocation: true` (a todo is added only when the user types the command) and `allowed-tools: Bash(~/.local/bin/fylgja todo add *)` |
| The skill directory is read from `~/.claude/skills/<name>/SKILL.md` (a personal skill) | `grep -n '~/.claude/skills' skills.md` | Personal skills live in `~/.claude/skills/<skill-name>/SKILL.md`, and the directory name is the command name unless `name` is set. | holds | `install skill --apply` links `~/.claude/skills/fylgja-todo` to the directory in dotfiles, as the existing skills are linked |
