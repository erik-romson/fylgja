## Answers to the five questions

### 1. Which commands list windows, workspaces, tabs and surfaces; do they report tty, pid, cwd or title?

The CLI has `list-windows`, `list-workspaces`, `list-panes`, `list-pane-surfaces`, `list-panels`, `tree [--all]
--json`, `top --processes`, `identify`, `current-window` and `current-workspace`. Handles are UUIDs, short refs
(`window:1`, `workspace:2`, `pane:3`, `surface:4`) or indexes (`--id-format refs|uuids|both`). From outside cmux every
one of them is refused (question 2), so the real field names were **not observed**, and neither the shipped help nor
the CLI contract names a tty or pid field. Verdict: `unknown`; the by-hand check is in the log.

Found instead: `cmux sessions [--json]` ("does not require a running cmux socket") prints cmux's own saved
agent-session records from `~/.cmuxterm/claude-hook-sessions.json`. Each Claude record carries `session_id`, `pid`,
`cwd`, `workspace_id`, `surface_id`, `agent_lifecycle` (`idle`, `running`, `needsInput`), `started_at`,
`updated_at`, `stored_pid_exists`, `active_for_surface`, `launch_arguments`, `stored_pid_arguments` and
`transcript_path`. Today it holds 9 records; 8 match a registry row on pid and session id, each with its own
workspace and surface (8 of 8 cmux-hosted rows); the ninth is stale. This is the best join source without a socket.
Two cautions: the file is an undocumented, version-1 format, and the argument arrays can hold secrets.

### 2. Does the CLI work from outside a cmux terminal, without the token, and from launchd?

No. In an environment without `CMUX_SOCKET_CAPABILITY` (checked by presence only) and with the `CMUX_*` ids unset,
`ping` and `list-windows` both answered `Access denied - only processes started inside cmux can connect`. The web
docs describe three modes: `Off`, `cmuxOnly` (default; only processes spawned inside cmux terminals) and
`allowAll` (no ancestry check; an environment override of the cmux process only). The wording is an ancestry check,
so the shell used here (not a cmux descendant) and a launchd job are in the same position. A real launchd run was
not done. `--password` and `CMUX_SOCKET_PASSWORD` exist; the docs do not say whether a password lifts the ancestry
check.

By-hand check for Erik (launchd context; it only runs a listing command and removes the job):

```sh
launchctl submit -l io.github.erik-romson.fylgja-cmux-probe \
  -o /tmp/fylgja-cmux-probe.out -e /tmp/fylgja-cmux-probe.err -- \
  /Applications/cmux.app/Contents/Resources/bin/cmux list-windows
sleep 2; cat /tmp/fylgja-cmux-probe.out /tmp/fylgja-cmux-probe.err
launchctl remove io.github.erik-romson.fylgja-cmux-probe
```

Expected: the same refusal. If it lists windows instead, the CLI becomes a usable join and focus method, and a
later record supersedes the CLI part of 0025.

### 3. Which commands select a workspace and surface; does selecting raise the macOS window?

CLI: `select-workspace --workspace <id>`, `focus-panel --panel <id>` (an alias over surface focus), `focus-pane`,
`focus-window --window <id>` ("bring to front") and `tab-action`. The docs do not say that selecting a workspace or
surface raises the macOS window: `unknown`. AppleScript (the app's `cmux.sdef`): `focus` on a terminal ("bringing its
window to the front"), `activate window`, and `select tab`, which selects a cmux workspace (the dictionary calls a
workspace a "tab"). A terminal has `id`, `name` (its title) and `working directory`. Not run. This is the
recommended focus alternative because it needs no cmux socket; it needs a TCC Automation grant, which the doctor
probes with a 3 s timeout (§4.4). Confirm by hand:

```sh
osascript -e 'tell application "cmux" to focus (first terminal whose id is "<surface-id>")'
```

with a surface id taken from `cmux sessions --all --json | jq -r '.sessions[0].surface_id'`, then check that the
right workspace is selected and the cmux window is frontmost. Whether a terminal `id` is the cmux surface id is
`unknown`.

### 4. The window-title format, and does it follow the selected tab?

One cmux window, on one AeroSpace workspace, for all 8 cmux-hosted sessions. Its title is a single token of 7
letters with no separator, path or digit. It equals a path component of 1 of the 9 recorded cwds and the basename of
none, so it is consistent with the name of the selected cmux workspace, not proven. It is not unique per session, so
it is not a join key. Whether it follows a tab or workspace switch needs a selection: `unknown`; the by-hand loop is
in the log.

### 5. What do cmux's own Claude hooks already record?

cmux starts `claude` with `--settings <temp file>`, one file per session (mode 0600, under the per-user temp tree).
The file holds `hooks` and `preferredNotifChannel` (`notifications_disabled`). Events and command shapes:

| Event | Command shape | Timeout |
|---|---|---|
| `SessionStart` | `cmux hooks enqueue claude session-start` | 5 s |
| `UserPromptSubmit` | `cmux hooks enqueue claude prompt-submit` | 5 s |
| `PreToolUse` (matcher `CronCreate`) | `cmux hooks claude cron-create-guard` | 5 s |
| `PreToolUse` | `cmux hooks enqueue claude pre-tool-use` | 5 s |
| `PostToolUse` (matcher `PushNotification`) | `cmux hooks enqueue claude push-notification` | 5 s |
| `Notification` | `cmux hooks enqueue claude notification` | 5 s |
| `PermissionRequest` | `cmux hooks feed --source claude` | 125 s |
| `Stop` | `cmux hooks enqueue claude stop`; `… claude feed`; async `cmux hooks claude auto-name` | 5 s, 5 s, 120 s |
| `SubagentStop` | `cmux hooks enqueue claude feed` | 5 s |
| `SessionEnd` | `cmux hooks enqueue claude session-end` | 5 s |

Each command is a shell snippet that runs only when `CMUX_SURFACE_ID` is set and `CMUX_CLAUDE_HOOKS_DISABLED` is
not 1, and passes `CMUX_CLAUDE_PID` and `CMUX_SOCKET_PATH` to the bundled CLI (`CMUX_BUNDLED_CLI_PATH`,
`CMUX_CLAUDE_HOOK_CMUX_BIN`). The file holds no literal token. What cmux records lands in the store file of question
1 (session, workspace, surface, pid, cwd, lifecycle, transcript) plus its own event and feed logs, which Fylgja does
not read. Fylgja's hooks therefore stay independent (`--settings` is per launch, and the commands do nothing outside
cmux); Fylgja reads the store only for the join and does not duplicate the lifecycle record.

## Decision in one paragraph

Join by hook-time ids (A3) from Phase 2 and, from Phase 1, by cmux's session store matched on session id and pid;
window level otherwise. Focus: AeroSpace window first, then the AppleScript `focus` on the surface's terminal
(by-hand confirmation before step 29), with window level as the fallback; the CLI only if it is ever reachable from
the daemon. The adapter reads the cmux version from `cmux --version` or `Info.plist` and degrades to window level on
an unknown version. See `docs/decisions/0025-cmux-join-and-focus.md`.
